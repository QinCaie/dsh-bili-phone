# dsh-bili-phone

每天在谷时随机挑一个时刻，让她用手机刷 B 站，刷完按自己的人格去 @ 人。

## 为什么不是「提醒她发消息」

唤醒和「刷完再分享」是两回事：

- 只唤醒 → 她大概率随口说一句，没有内容
- 注入任务 → 她真的去打开 B 站、看几条、挑一条有意思的再开口

所以插件在叫醒那一刻把任务原文塞进她那一轮。

## 分工

| 谁 | 干什么 |
| --- | --- |
| 插件 | 算今天几点（谷时窗口内随机）、到点叫醒、注入任务 |
| 她的工具 | `mcp__phone__*`（开 B 站、截图、滑动、看内容）、`mcp__snowluma__qq_send_message`（@ 人） |

## 工具

| 工具 | 作用 |
| --- | --- |
| `bili_phone_status` | 今天刷没刷、上次什么时候 |
| `bili_phone_now` | 立刻刷一次（不占今日名额） |

## 路由

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/bili-phone/status` | 今日状态 |
| POST | `/api/bili-phone/now` | 立刻触发 |
| GET/POST | `/api/bili-phone/config` | 时间窗与每日次数 |

## 配置

`config.json` 里是时间窗（谷时）与次数上限。

## 依赖

- 桥接在跑（唤醒走 `/api/socialV2/wake`）
- 手机端（dafeiyu-phone）在线，能开 B 站
- QQ 线（SnowLuma）能发消息
